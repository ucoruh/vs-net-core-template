.NET Core Project Template

A C# / .NET solution template for course term projects: a class library, a thin console app, xUnit tests, code and documentation coverage generated with both ReportGenerator and the native lcov/genhtml tooling side by side, Doxygen and DocFX API docs — per platform (Windows and Linux/WSL) — a MkDocs Material site, and local + CI/CD release packaging, all driven by a handful of numbered scripts.

Live site: https://ucoruh.github.io/vs-net-core-template/ (English) · https://ucoruh.github.io/vs-net-core-template/tr/ (Türkçe) — one bilingual MkDocs Material site (mkdocs-static-i18n, language switcher in the header; the DocFX API reference lives under /native/).

1. Start your own PRIVATE repository from this template

  1. Click Use this template → Create a new repository (green button, top right). Do not fork: a fork of a public repository cannot be made private.
  2. Choose your account, name the repository after your project, select Private, click Create repository.
  3. In your new repository: Settings → Collaborators → Add people → add the instructor (ucoruh) and your team mates.
  4. Clone it and build (below).

A private repository on GitHub Free has no GitHub Pages: show your project locally instead (7-build-all + 9-open-site, plus the release/ folder) — see Showing your project without GitHub Pages · Türkçe. Releases work on private repositories.

# Linux / WSL
chmod +x *.sh scripts/*.sh
./4-install-tools-linux.sh
./6-build-and-test-linux.sh
./7-build-all-linux.sh
./9-open-site-linux.sh

9-open-site serves the built site at http://localhost:8080/; open that URL rather than double-clicking site/index.html, so the embedded report frames load. Everything is documented in the guides below.

Project identity: project.env

PROJECT_NAME=calculator, VERSION=2.1.1 (plus the solution/project paths). Every script and the CI workflow read this one file; rename your project there. Release assets are named <project>-<version>[-<platform>[-<arch>]]-<content>[-<tool>].<ext> (platform windows | linux | macos; WSL is linux).

Scripts: same number = same job, platform as suffix

Script Job
1-configure-git-hooks-<platform> install the pre-commit hook
2-create-gitignore-<platform> regenerate .gitignore (keeps the project section)
3-install-package-manager-windows.bat Chocolatey + Scoop (Windows only)
4-install-tools-<platform> .NET SDK, Doxygen, lcov, astyle, dotnet tools, MkDocs Material, coverxygen
5-format-code-<platform> astyle
6-build-and-test-<platform> fast: build + unit tests
7-build-all-<platform> + coverage (both families), doc coverage (both), Doxygen + DocFX, app, site, release/
8-run-app-<platform> run the sample app
9-open-site-<platform> serve the site on localhost and open it
10-release-<platform> [--dry-run] publish release/ as a GitHub Release with gh
11-clean-<platform> delete every generated folder

<platform> is windows (.bat) or linux (.sh; native Linux and WSL). Helpers live in scripts/.
